## 1. What we are building

**One-line pitch:** *For every decision your team made, see the code AI wrote because of it, who reviewed that code, and what it cost in Bobcoins. When a decision drifts, you know exactly what code to revisit.*

The product answers three questions about AI-assisted engineering. Each one comes from one existing project:

| Question | Lens in the product | Comes from | Today |
| --- | --- | --- | --- |
| **Why** was it decided, and is that still true? | Decision Cockpit (graph, time slider, drift alerts) | **Bob Time Machine** (`main` branch, Next.js) | Hard-coded demo graph for ADR-104 |
| **Who/what** wrote this code, and did a human review it? | AI Code Ledger, plus VS Code gutter and hover | **Provenance** (`provenance` branch, TypeScript monorepo) | Real: sessions in git, `prov` CLI, MCP server, VS Code extension |
| **What did it cost?** | Spend column, plus the personal Bob Analytics dashboard | **Bob Analytics** (`bob_analytics` branch, `bob-analytics/` folder, Python stdlib) | Real: reads `~/.bob/db/bob.db` read-only |

### How the three connect (the new parts)

1. **Decision → code.** A Provenance session gains an optional `decisionRefs` field (for example `["ADR-104"]`). Bob fills it through the MCP tool when it records a session. A new `prov impact <ref>` command gives the **blast radius** of a decision: its sessions, the lines that survive at HEAD, and how many of those are unreviewed or rejected.
2. **Code → cost.** A new `export.py` in Bob Analytics matches each Provenance session to the Bob task that produced it (same folder, matching time window). It reports that task's Bobcoin cost.
3. **One cockpit.** The Next.js app reads both through server-side API routes. It draws AI sessions as nodes in the decision graph, shows the blast radius (lines and Bobcoins) inside the drift alert, and adds an **AI Code Ledger** page. The slider's zero-hindsight rule now covers code too: rewind to Dec 12, 2024 and the sessions disappear.

### Demo story (one fictional payments team, consistent everywhere)

- Nov 28, 2024: Black Friday outage `RCA-2024-88` (existing node).
- Dec 2, 2024: CISO FedRAMP mandate `CISO-2024-12` (existing node).
- Dec 12, 2024: `ADR-104` ratifies OpenShift because EKS lacked FedRAMP High (`ASM-104-03`).
- Jan–Jun 2025: Bob writes the payments service code under ADR-104 (the Provenance demo repo, now dated 2025): session A (retry/backoff, approved), B and C (refund validation and tests, unreviewed), a human edit, and D ("log card numbers", rejected as PII).
- Mar 3, 2026: AWS bulletin invalidates `ASM-104-03`, and a drift alert fires on ADR-104 (existing).
- **New in the alert:** "Code built on ADR-104: 4 AI sessions · 49 lines at HEAD · 33 unreviewed (2 rejected) · 7.35 Bobcoins."

### M2. Provenance: decision references and impact

All logic goes in `packages/core`. `cli`, `mcp-server` and `vscode-extension` stay thin wrappers.

**2a. Schema** (`packages/core/src/schema.ts`):
```ts
export const DecisionRefSchema = z.string().regex(/^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$/, "invalid decision ref");
// in SessionSchema, after filesChanged:
decisionRefs: z.array(DecisionRefSchema).max(20).optional(),
```
- Keep it `.optional()` with **no default**, so existing session files and existing `toEqual` tests are unchanged. `version` stays `1`.
- `store.ts`: add `decisionRefs?: string[]` to `NewSessionInput`. `createSession` de-duplicates the refs, keeps their order, and leaves the key out when the list is empty. `importSession` keeps the field, because the schema now allows it.

**2b. Report rows** (`report.ts`): add `decisionRefs: string[]` to `SessionRow`, filled from `s.decisionRefs ?? []`. **Do not** render it in Markdown or HTML, so the two snapshot files stay byte-identical.

**2c. Impact** (new `packages/core/src/impact.ts`, exported from `index.ts`):
```ts
export interface DecisionImpact {
  ref: string;
  sessionIds: string[];                 // sessions whose decisionRefs include ref (exact, case-sensitive), by createdAt
  totals: { sessions: number; survivingLines: number; unreviewedLines: number; rejectedLines: number };
  ranges: UnreviewedRange[];            // report.unreviewed + report.rejected entries for those sessions, sorted file, then start
}
export function decisionImpact(report: ReportData, ref: string): DecisionImpact;
export function allDecisionImpacts(report: ReportData): DecisionImpact[]; // every ref used by any session, sorted by ref
```
- `survivingLines` is the sum of `SessionRow.survivingLines`. `unreviewedLines` is that sum over sessions whose status is not `approved`, so rejected counts as unreviewed (same rule as Provenance DECISIONS #29). `rejectedLines` is the sum over `rejected` sessions.
- An unknown ref returns zero totals, not an error.

**2d. CLI** (`cli.ts`):

- `prov impact [ref] [--since <date>]`: builds `generateReport(root, { since })`, then calls `decisionImpact` (with a ref) or `allDecisionImpacts` (without one). With `--json` it prints `DecisionImpact` or `{ "decisions": DecisionImpact[] }`. Text output is one line per ref: `ADR-104  4 sessions · 49 lines · 33 unreviewed (2 rejected)`.

### M3. Analytics: cost per Provenance session

Do **not** change `compute()`, `server.py`, the web dashboard or any security behaviour. All 54 existing tests must still pass unchanged.

**3a. `analytics.py`**: add one public function next to `compute`:
```python
def task_costs(tasks, messages, mult=1.0):
    """Per-task Bobcoin cost, using exactly the rule compute() uses.
    cost = max(task.costs.cost, sum of assistant spend.cost) * mult.
    A task with task_type == "subagent" and a parent_id adds its cost to the parent and is not returned itself.
    Returns {task_id: {"cost", "project_id", "created_at", "updated_at"}}; times are ms since epoch."""
```
Add a test: for every existing fixture used in `test_analytics.py`, `sum(task_costs(...)[*].cost)` equals `compute(...)["totals"]["cost"]` within 1e-6.

**3b. New `apps/analytics/provenance_join.py`** (stdlib only, pure functions):
- `load_sessions(repo)`: reads `repo/.provenance/sessions/*.json`. Skip files whose stem does not match `^[0-9A-HJKMNP-TV-Z]{26}$`, and files that do not parse. Return `[{id, createdAt_ms, decisionRefs}]`. Never follow paths outside `repo/.provenance/sessions`.
- `match_sessions(sessions, task_costs, repo)`: candidate tasks are those whose `project_id`, without a leading `file:`, has `os.path.realpath` equal to `os.path.realpath(repo)`. A session matches a task when `created_at <= session_ms <= updated_at + 15 min`. If several tasks match, take the one with the latest `created_at`. If several sessions match the same task, split that task's cost evenly between them and set `sharedWith` to the count.
- Output per session: `{"sessionId", "taskId" | None, "cost" | None, "match": "time-window" | "none", "sharedWith": int}`. Round cost to 4 decimals.

**3c. New `apps/analytics/export.py`** (CLI):
```
python3 apps/analytics/export.py --repo <path> [--db <path>] [--config <path>]
```
- `--db` defaults to `db_path` from the config (`--config` defaults to `~/.bob-dashboard/config.json`, then `DEFAULT_CONFIG`). The cost multiplier comes from the config.
- Open the database only through `analytics.read_db` (read-only).
- Print exactly one JSON object to stdout:
  ```json
  { "unit": "Bobcoins", "generatedAt": "…", "matchRule": "time-window",
    "sessions": [ { "sessionId": "…", "taskId": "…", "cost": 3.42, "match": "time-window", "sharedWith": 1 } ],
    "totals": { "matchedCost": 7.35, "matchedSessions": 4, "unmatchedSessions": 0 } }
  ```
- Exit codes: `0` ok; `2` database not found (prints `{"error": "Bob database not found"}`); `1` anything else (generic message, no stack trace, no prompt text). **Never print prompt text.** This output contains ids and costs only.

export type LedgerResponse =

      rows: LedgerRow[]; totals: LedgerTotals; impacts: DecisionImpactWithCost[] }

**5b. Pure modules.** No React, Next or Node imports; use `import type` only. Unit-test these under `apps/web/test/`:
- `src/lib/ledger.ts`:
  - `joinLedger(report, impacts, spend | null): LedgerResponse` merges the prov report JSON, the `prov impact --json` output and the export output by `sessionId`.
  - A cost total is `null` when spend is unavailable.
  - `costPerSurvivingLine = aiCost / Σ survivingLines`, or null when there are 0 lines.
  - Round money to 2 decimals for display only; keep raw numbers in the data.
- `src/lib/sessionGraph.ts`:
  - `buildSessionGraph(baseNodes, baseEdges, rows)` returns `{ nodes, edges }`. Each row becomes a node: `id: 'session-' + sessionId`, `type: 'session'`, `title` = prompt excerpt cut to 60 characters, `description` = `` `${survivingLines} lines at HEAD · ${status}` `` plus ` · ${cost} Bobcoins (est.)` when the cost is known, `timestamp: createdAt`, `status`, `confidence: 1`, `stakeholders: [agent, reviewer].filter(Boolean)`.
  - Session nodes sit in a row sorted by `createdAt`: `position: { x: 50 + i * 330, y: 640 }`.

  - `impactAsOf(rows, ref, epoch)`: totals over rows where `Date.parse(createdAt) <= Date.parse(epoch + 'T23:59:59Z')` and `decisionRefs` includes `ref`. Returns `{sessions, survivingLines, unreviewedLines, rejectedLines, cost}`.
